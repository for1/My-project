# 02 · 精度：怎么定义、怎么测、怎么在现场保证

## 1. 先把目标翻译成可检验的指标

用户要求「高精度（1cm 范围内）识别尺寸和角度」，最终选择的口径是
**相对误差 ≤ 1%**（5 m 墙允许 ±50 mm）。

工程上把它拆成三个可独立测量的指标：

| 指标 | 定义 | 目标 | 实测（合成数据） |
|---|---|---|---|
| 墙面位置误差 | 每面真值墙中点到最近重建墙轴线的**垂直距离** | ≤ 10 mm | mean **2.06 mm**，max **5.47 mm**（基线） |
| 墙面角度误差 | 对应墙方向角之差 | ≤ 0.1° | ≤ 0.05°（主方向估计精度） |
| 房间净面积误差 | 同位置房间净面积之差 | ≤ 0.3% | 最大 **0.11%**（0.006 m² / 5 m²） |

判定用的门槛写在 `tools/check_recon_suite.py` 里：**mean ≤ 20 mm 且房间数完全正确**。

---

## 2. 为什么能测：合成真值

真机数据没有精确真值，所以精度验证用「已知户型 → 渲染点云 → 重建 → 比对」闭环：

```
samples.demo_apartment()            已知真值户型（10m×8m，9 墙、6 房间，尺寸全部精确）
        │
        ├─ 墙面均匀撒点（可配间距）
        ├─ 高斯深度噪声（可配 σ）
        ├─ 视点遮挡剔除（每个房间中心站一个人，掠射角看不到的表面丢掉）
        ├─ 随机丢弃（模拟反光/玻璃/暗角）
        ├─ 家具盒子（制造非墙面垂直平面干扰）
        └─ 地面/天花
        ▼
     cloud.ply  ──►  reconstruct()  ──►  重建户型
                                          │
                              truth ──────┴──► accuracy.compare_plans()
```

`reconstruct/synthetic.py` 里模拟的每一种退化都对应真机上的一个具体问题，
所以调参不是"对着一个用例过拟合"，而是对着 7 种工况同时达标。

## 3. 误差来源分解

| 来源 | 量级 | 是否可消除 | 处理方式 |
|---|---|---|---|
| 深度传感器噪声 | 0.5~2 cm（随距离平方增长） | 部分 | 体素化（3cm）平均、平面拟合、按置信度过滤 |
| 主方向估计误差 | 无改进前 **0.50°** → 改进后 **0.06°** | 是 | 四倍角圆周均值（见下） |
| 平面聚类把两个墙面并成一团 | 无改进前 rms **40~50 mm** | 是 | 直方图峰检测代替间隔聚类（见下） |
| 家具侧壁污染墙长 | 可达 **3 m** 虚假延伸 | 是 | 按"是否到墙顶"裁剪延伸段（见下） |
| 窗洞切断墙面 | 墙面被切成两段 | 是 | 允许填补 ≤2.2 m 的洞口缺口 |
| 拐角遮挡导致墙短 | 10~30 cm | 是 | 拐角补全（端点吸附 + 延伸到交点） |
| 玻璃/镜面/纯白墙缺失 | 局部成片丢点 | 否 | 采集时避开；缺失不致命（墙仍能由相邻面配对推定） |
| IMU/位姿漂移（整户长距离） | 千分之几，随面积增长 | 部分 | 曼哈顿约束 + 房间闭合；**现场一次等比标定**兜底 |
| 整体比例偏差（深度标定误差） | 0.5~2% | 是 | **现场标定**（见第 5 节） |

### 三个"从失败到达标"的关键修正

这三个是本项目调试过程中真实踩到的坑，也是同类工具最容易忽略的地方：

**① 主方向估计：直方图峰值 → 四倍角圆周均值**

曼哈顿假设下，墙面法向只可能是 θ、θ+90°、θ+180°、θ+270°。
把这四个角乘 4 之后全部重合到 4θ，于是可以直接做圆周平均：

```python
z = mean(exp(4j * arctan2(ny, nx)))
yaw = angle(z) / 4
```

比取直方图峰值精确一个数量级（实测 0.50° → 0.06°），而且不需要调 bin 宽度。
0.5° 的旋转误差在 10 m 跨度上就是 87 mm —— 这一项就足以让精度不达标。

**② 墙面聚类：间隔聚类 → 直方图峰检测**

门窗洞口的**侧壁**（门套、窗洞侧边）会在墙面 A 与墙面 B 之间连续撒点。
按"间隔 > 4.5cm 就断开"做一维聚类时，这些桥接点让两个墙面无法分开，
表现为一簇的 rms 从 4.5 mm 恶化到 40~50 mm、点数严重偏少，
后续配对随之失败（只配出 1 面墙）。

改成直方图峰检测后：只在密度峰附近取点，中间的低密度桥接点自然被忽略。
同一份数据立刻变成 14 个面、rms 4.2~5.0 mm、9 面墙全部正确配对。

**③ 墙长裁剪：按密度 → 按"是否到顶"**

同一坐标上可能既有通高真墙，也有隔壁房间半人高家具的侧面。
最初按沿墙方向的**点密度**裁尾巴 —— 结果误伤了掠射角墙端（那本来就是稀疏的），
一面 8 m 的墙被裁到 3.5 m。

改成**高度判据**：墙一定通到墙顶，家具一定到不了。
以该平面 95 分位高度作为墙顶参考，只有"本 bin 内最高点接近墙顶"的区间才算墙。
这个判据不受采样密度影响。再叠加"洞口缺口允许填补（≤2.2 m）"，
既不会被家具带长，也不会被窗洞切断。

## 4. 现场怎么保证精度（验收流程）

算法给的是**几何相对精度**；整机测量精度还取决于采集质量与尺度标定。
建议按下面流程验收（也写进了 `android/README.md`）：

1. **采集**：每间房绕墙一圈，离墙 0.5~3 m，速度 ≤0.5 m/s，相邻房间同一次扫完。
2. **重建**：`python -m scan2plan recon cloud.ply -o out.json`
3. **看诊断**：`python -m scan2plan info out.json`
   - 房间数是否合理
   - `problems` 里有没有"悬空墙端点"（说明某个角没闭合 → 回现场补扫那一角）
4. **等比标定**（**必须做**）：
   用激光测距仪量一段尽量长的墙（建议 >3 m，越长标定越准），
   然后在编辑器里直接改这面墙的长度为实测值 —— 全图会等比缩放。
   代码里等价于 `fp.calibrate_by_wall(wall_id, measured_m)`。
5. **抽检**：再量 3~5 段不同方向、不同房间的墙，与模型对比。
   - 若误差都在 ±1% 内 → 通过
   - 若有系统性比例差 → 重新标定（换更长基准墙）
   - 若个别墙偏差大 → 看该墙是否被家具/玻璃干扰，现场补扫
6. **角度抽检**：用编辑器选中墙体，右侧面板直接显示角度值。
   正交户型应接近 0/90°，允许 ±0.2°。

### 关于「1cm 以内」

- 若 5 m 跨度按 ±1% 算，允许 ±50 mm，**有 5 倍余量**。
- 若用户期望的是"任何一段 1 m 的尺寸误差 ≤10 mm"（即 1% 局部），
  算法链路实测 2~9 mm，**满足**。
- 若期望"整户绝对误差 ≤10 mm 且不做任何标定"，则需要毫米级深度标定的设备
  （ARCore 消费级深度做不到），这不在本工具的能力范围内。
  这是必须在需求阶段说清楚的边界 —— 本项目选择的口径是相对误差 ≤1%。

## 5. 报告里每个数字怎么算出来的

`reconstruct/accuracy.py`：

```python
# 墙面位置误差
对每面真值墙 tw：
  在重建墙里找方向差 < 5° 的候选
  取「中点到候选墙轴线的垂直距离 + 0.5 × 真值墙采样点到候选墙的距离最大值」最小者
  记录垂直距离（mm）与角度差（°）
汇总：mean / p95 / max，以及 ≤5/10/20/50 mm 的命中率

# 房间面积误差
对每个真值房间：按质心落在哪个重建房间里配对（落不进去就取最近的，限 2.5 m）
  记录 abs_error（m²）与 rel_error（%）
```

注意这个指标是**几何重建误差**，不包含传感器标定误差与 IMU 漂移 ——
所以真机验收必须以第 4 节的现场流程为准。把两者混为一谈是这类工具最常见的夸大方式。
